# 013 — Tushare 限频治理与分段拉取

## 目标

让 `TushareFetcher` 在长区间 / 高频拉取下更稳健：**超长区间分段拉取**、**请求间隔节流**、**失败重试**，并在积分 / 权限不足时给出**可读的积分提示**。

## 背景 / 动机

009 一期的 `TushareFetcher` 为最小实现——单次 `pro_bar`、失败即抛错。Tushare 按积分限频，单次返回行数有上限（通常 5000~8000 行/调用），长区间（如 10 年日线 ≈ 2400 行尚可，但分钟线或大批标的会触顶）；并发拉取易触发限频。随着 011 首页「刷新行情」、012 ETF 流向等拉取入口增多，需补限频治理。

## 要点

- **分段**：按年（或固定行数窗口）切分 `[start, end]`，逐段 `pro_bar` 后合并、去重、升序。
- **节流**：进程内最小请求间隔（如 200~300ms），避免连发触发限频。
- **重试**：网络错误 / 限频（特定 msg）退避重试 N 次；积分不足不重试、直接抛带「积分不足，需 XXXX 积分」的中文提示。
- **复用**：仍走「先查本地表 → 仅补缺失子区间 → UPSERT」（`ensure_price_data`），分段只作用于真正需要网络请求的子区间。
- 列入可选配置（间隔 / 分段大小）。
